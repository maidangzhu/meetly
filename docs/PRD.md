# Meetly

Meetly 帮助听众在听一场会的时候看懂行业术语。它是 macOS 上的本地优先悬浮窗：采集会议声音，转成文字，再按所选行业解释转写里的缩写和行话。

## 用户在做什么

用户正在听，不是在面试，也不是在向助手提问。例如听众在 CRO / 临床研究的会里听到 CTA、CRA、GCP，但不一定知道这些缩写在这个行业里指什么。术语出现时，Meetly 用大字给出一句口语解释。

## 一场会怎么开始

开始聆听前选择行业。预设：

- CRO / 临床研究
- IT
- 建筑
- 电商
- 金融
- 医疗
- 制造
- 教育

列表之外可以选「其他」并自己填写。上次的选择会记住，下一次打开时还在。

声音来源：

- 远程会议：系统播放的声音，加上麦克风。
- 现场会议：只听麦克风。

设置窗口在菜单栏里，用来保存行业、转写 API Key、语言模型 API Key，以及查看音频状态。开会时的悬浮窗不再放第二套设置。

## 术语卡

新的转写句子会连同当前行业发给用户自己的语言模型。模型只返回 JSON：

- 没有需要解释的术语：`{ "terms": [] }`，界面保持安静。
- 有术语：短列表 `{ "term", "explanation" }`。解释是一两句口语中文，不给话术，不说「你应该说」。

同一场里，规范化后的同一个术语只解释一次。一句里可以记下多个术语，最新的一个用大约 64px 的大字显示，之前的留在小列表里。不确定、只是日常用词，或当前行业里仍有两种说得通的意思时，不弹出卡片，也不显示思考占位。

同一个缩写按所选行业解释，应用里没有私有词表。提示词里的例子只说明这条规则：行业是 CRO / 临床研究时，CTA 指临床试验助理（Clinical Trial Assistant），不是临床委托协议，也不是 call-to-action。行业是电商时，CTA 可以指行动号召（call to action）。不要把一个行业的展开套到另一个行业上。

没有术语时，悬浮窗只显示正在听的状态和行业名称。

## 不做的事

- 全局听写，包括 Fn+Space。
- 按住 Fn 向助手提问。
- 主动教练、下一步建议、聊天时间线。
- 面试官 / 候选人角色。
- 为了有内容而说话。

## 平台

当前只做 macOS。密钥留在本机。不承诺悬浮窗在所有会议软件的录屏里都不可见。
